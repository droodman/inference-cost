No standard errors: the response is the empirical Pareto frontier P_t(c) sampled at the nodes of the envelope's fixed cost-date grid, and grid nodes are not observations. N is the nodes at which the frontier is defined; they resample a few dozen staircase corners, so N measures resolution, not information. BC columns are a Box-Cox alternative to the quadratic: the index is linear in phi(cost), phi(time) and their product, with phi(x; lambda) = (x^lambda - 1)/lambda (log at lambda = 0) applied to LEVEL cost per task and to years since mid-2020, GPT-3's release -- so the BC intercept is the fit at $1 per task in mid-2021, where both transforms vanish. phi is increasing whatever lambda is, so the surface is monotone in cost at every date -- the quadratic's bending back toward the data cannot happen -- while the product term still allows the cost slope one sign change over time. These are BOX-TIDWELL fits: phi acts on the REGRESSORS only and the index is the plain logit, so no Jacobian arises. A response-side lambda on the odds was tried and removed -- a transformed response has to be inverted to be read back, and that inverse has a pole at a finite index which the profile walked into. The lambdas are estimated per benchmark by profiling the probability-scale quasi-likelihood, and are reported without standard errors: the profile provides none, and this model reports none anywhere. The BC specification nests the linear one (lambda_cost = 0, lambda_time = 1, no product term) but not the quadratic. fm13's five months of data sit 5.7-6.1 years from the origin, over which every lambda_time fits alike, so lambda_time is fixed at 1 there rather than estimated; elsewhere it is weakly identified and best read as a shape the data tolerates rather than demands -- a lambda_time of exactly 3 or -2 sits on the edge of the search box, the flat profile having run to the wall. This table has no pooled column: per-benchmark lambdas put the BC slopes on different transforms, leaving no common scale for the alpha-weighted average to land on.
