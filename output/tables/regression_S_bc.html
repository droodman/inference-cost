Robust (HC1) standard errors: the quasibinomial objective is a quasi-likelihood, so inverse-Hessian errors would be wrong. BC columns are a Box-Cox alternative to the quadratic: the index is linear in phi(cost), phi(time) and their product, with phi(x; lambda) = (x^lambda - 1)/lambda (log at lambda = 0) applied to LEVEL cost per task and to years since November 18, 2021, when the GPT-3 API became generally available -- so the BC intercept is the fit at $1 per task on November 18, 2022, where both transforms vanish. phi is increasing whatever lambda is, so the surface is monotone in cost at every date -- the quadratic's bending back toward the data cannot happen -- while the product term still allows the cost slope one sign change over time. These are BOX-TIDWELL fits: phi acts on the REGRESSORS only and the index is the plain logit, so no Jacobian arises. A response-side lambda on the odds was tried and removed -- a transformed response has to be inverted to be read back, and that inverse has a pole at a finite index which the profile walked into. The lambdas are estimated per benchmark by profiling the quasibinomial deviance, and are reported without standard errors: the profile provides none, and the coefficient standard errors are conditional on the profiled lambdas -- they carry no lambda uncertainty. The BC specification nests the linear one (lambda_cost = 0, lambda_time = 1, no product term) but not the quadratic. fm13's five months of data sit 5.7-6.1 years from the origin, over which every lambda_time fits alike, so lambda_time is fixed at 1 there rather than estimated; elsewhere it is weakly identified and best read as a shape the data tolerates rather than demands -- a lambda_time whose profile runs to the edge of its search box ([-8, 8]) is treated as unidentified and locked at 1. This table has no summary column: the average column's content is the cost drop row, which only the linear specification carries.
